# 番号识别模式设计

## 目标

在现有聚合搜索中增加一个明确、可关闭的“番号识别”模式。用户输入常见的字母数字编号后，SeedStream 在本机统一大小写、全角字符和分隔符，使用少量等价写法查询已经启用的搜索源，并优先显示标题中精确包含该编号的结果。

界面保持中性，不标注内容类别，也不内置新的特定站点或编号数据库。搜索范围仍由内置公共来源和用户自行配置的 Torznab 来源决定。

## 交互

- 聚合搜索输入框下方增加“番号识别”开关，默认关闭，不改变现有普通搜索。
- 打开后实时显示识别结果，例如“识别为 SSIS-123 · 将匹配常见写法”。
- 无法识别时显示“未识别到规范番号”，提交搜索会给出明确错误，不回退为宽泛关键词搜索。
- 成功搜索后，结果标题中精确包含番号的卡片显示“番号精确”标记。
- 推荐排序优先比较精确匹配，再比较现有的可导入性、节点和发布日期；手动选择节点、日期或容量排序时保持用户选择。

## 识别规则

- 先使用 Unicode NFKC 处理全角字符，再转为大写并统一空格、下划线和连字符。
- 支持常见前缀加数字形式，例如 `SSIS-123`、`SSIS123`、`HEYZO 1234`。
- 支持带数字前缀的形式，例如 `259LUXU-1234`。
- 支持 `FC2-PPV-1234567` 及其紧凑或空格写法。
- 输入必须同时包含字母和数字，拒绝普通句子、URL、磁力链接、纯数字和过长内容。
- 每次最多生成三条查询：规范连字符形式、紧凑形式和空格形式，避免对搜索源产生无界请求。

## 数据流

1. 渲染进程只把 `{ query, mode }` 发送给现有搜索 IPC。
2. 主进程重新执行完整验证，生成受限的查询变体；渲染端预览不作为信任边界。
3. 每个启用的搜索源依次尝试这些变体，单个来源的结果先合并，再进入现有的跨来源去重。
4. 排序层按规范编号计算标题匹配等级，公开给渲染进程的结果只包含布尔匹配标记，不泄露磁力链接或 API 密钥。

## 安全与性能边界

- 不抓取或内置任何新站点，不改变隔离网页窗口与 API 密钥的安全边界。
- 识别只在本机执行，不产生遥测或历史记录。
- 搜索变体固定最多三条，沿用每次请求的超时、响应体上限、内容类型校验和一次性导入令牌。
- 普通搜索继续接受字符串调用，保证现有 IPC 和测试兼容。

## 验证

- 单元测试覆盖全角字符、紧凑写法、FC2 写法、数字前缀、非法输入和变体上限。
- 服务测试验证多个变体确实发送、重复结果合并、精确编号优先和普通搜索行为不变。
- 渲染辅助测试验证推荐排序和识别提示。
- 运行完整测试、回环 smoke、Electron 启动与界面交互验证，再构建 macOS 和 Windows 安装包。
