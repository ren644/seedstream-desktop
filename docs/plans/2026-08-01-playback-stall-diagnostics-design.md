# SeedStream 播放缓冲诊断设计

## 问题

当前播放器在任务没有任何可用节点时仍持续显示“正在缓冲分片”，任务标签也无条件显示“边下边播”。WebTorrent 默认每 30 秒才检查一次无节点状态，因此用户会长时间看到一个无法解释的转圈界面。截图中的 `节点 0`、`下行 0 B/s` 和 `进度 0%` 说明播放器尚未收到任何视频数据。此外，文件名中的 MKV 与 AC3 组合即使取得数据，也可能超出 Electron/Chromium 的内置解码能力。

## 方案比较

1. 给所有任务追加公共 Tracker：有时能增加节点，但会改变种子的发现范围，违反私有种子的约束，也无法解决真正无人做种的情况，因此不采用。
2. 预先下载固定大小再播放：可以改善已有节点时的首播稳定性，但播放器的 HTTP Range 迭代器已经会优先请求当前播放位置；对零节点无效，还会增加不必要缓存，因此不作为本次修复。
3. 缩短无节点检测并建立播放健康状态：保留原始 Tracker、DHT 和私有种子规则，在 12 秒左右明确区分“寻找节点”“无可用节点”“节点无数据”和“正在缓冲”，同时提供重新连接入口。该方案直接修复误导状态，风险最低，采用此方案。

## 设计

- 每个 WebTorrent 传输将无节点检查间隔设为 10 秒；渲染层保留 12 秒发现宽限期，避免刚启动就误报。
- 新增纯函数播放健康判断，输入节点数、下载速度、数据是否前进、媒体元素状态和等待时长，输出状态文案、解释与是否显示重连按钮。
- 播放请求不等待 `HTMLMediaElement.play()` 的 Promise；零节点时该 Promise 可能长期未决，等待它会把全局 busy 状态和所有操作按钮一起锁死。
- “重新连接”会先关闭当前临时播放并清理缓存，再重新加入同一个种子，重新触发该种子原有的 Tracker/DHT 发现流程。
- 播放停止时重置旧的无节点标记，防止重连任务继承过期状态。
- 根据文件名给出保守的容器/编码兼容性提醒。只提示风险，不把文件名当作真实媒体探测结果。
- 不更改缓存隔离、退出清理、私有种子语义或永久下载行为。

## 验证

- 单元测试覆盖发现宽限、无节点、已连接但无数据、恢复缓冲、可播放和兼容性提示。
- 回归测试验证媒体播放 Promise 永久未决时，启动函数仍立即返回，不会锁住界面。
- 引擎测试验证无节点检查间隔、节点事件切换与关闭播放后的状态重置。
- 运行完整测试、真实本机回环 Range 流测试、Electron UI smoke test。
- 构建 macOS arm64 和 Windows x64 安装包，检查产物及校验和。
