# SeedStream 搜索中心设计

## 目标

在现有 SeedStream 中加入一个私有化的资源搜索中心，让用户不必先在浏览器下载 `.torrent` 文件，也能从聚合结果、隔离网页或磁力链接直接创建任务，并继续使用现有的在线播放、永久下载、本地播放和缓存清理能力。

搜索中心不替用户判断内容授权。界面会保留简短提示，具体搜索源、账号和 API 密钥由本机用户管理。

## 交互

顶部增加“搜索资源”按钮，打开与现有工业控制台风格一致的全宽抽屉。抽屉包含三个入口：

1. **聚合搜索**：同时查询内置来源和用户配置的 Torznab 来源。结果展示标题、容量、来源、发布时间、做种数和下载数；默认优先展示更可能快速连接的结果。
2. **网页捕获**：在独立、沙盒化的搜索窗口中打开关键词或自定义网址。网页点击磁力链接或 `.torrent` 下载时，SeedStream 弹出确认并加入任务。
3. **磁力链接**：粘贴 `magnet:` 链接后直接解析，适合从聊天、网页或私有系统复制资源。

搜索结果加入任务后自动关闭抽屉并选中新任务。真正开始播放或下载仍由用户点击，避免误触后立即产生网络传输。

## 架构与数据流

渲染进程只负责输入和展示，不直接访问互联网。主进程新增 `SearchService`，并通过受信 IPC 暴露最小能力：读取来源、保存来源、执行搜索、导入结果、打开隔离窗口和清理浏览数据。

`SearchService` 使用提供器适配层：

- `InternetArchiveProvider` 作为无需配置的内置来源。
- `TorznabProvider` 兼容 Jackett、Prowlarr 和其他 Torznab 服务。
- `SearchBrowser` 负责用户自行访问的网页，不解析网页正文，只捕获用户点击的磁力链接和 `.torrent` 下载。

统一结果模型包含 `sourceId`、`title`、`size`、`seeders`、`peers`、`publishedAt`、`detailsUrl`、`torrentUrl`、`magnetUri` 和 `infoHash`。优先按 info hash 去重；缺少 hash 时使用规范化标题与容量去重。排序综合可连接节点、信息完整度和发布时间，不承诺实际速度。

现有 `TorrentEngine` 增加磁力链接导入。远程 `.torrent` 下载先经过大小、协议、超时和内容校验，再复用 `importTorrentBuffer`，因此不会绕开已有路径安全与任务去重逻辑。

## 私有配置与安全边界

搜索源配置写入 SeedStream 用户数据目录。Torznab API 密钥优先用 Electron `safeStorage` 加密；系统加密不可用时不持久化密钥，并在设置中提示。URL 只接受 HTTP/HTTPS，拒绝内嵌用户名密码。响应设置 15 秒超时，搜索文档上限 8 MB，种子文件上限 10 MB。

网页捕获使用独立 `BrowserWindow`：`sandbox: true`、`nodeIntegration: false`、`contextIsolation: true`，禁止网页调用 SeedStream IPC、打开本地文件或创建不受控窗口。浏览会话与主界面隔离；提供“一键清理网页数据”，应用退出时清理 HTTP 缓存和临时 `.torrent` 文件。登录 Cookie 默认保留，方便私有来源重复使用，用户可主动清除。

磁力链接必须通过协议和长度校验。网页捕获到链接后只加入待选任务，不自动播放。错误按来源独立显示：单个来源超时不会让整次搜索失败；所有来源失败时给出可操作的诊断。

## 测试与发布

单元测试覆盖查询清理、URL/磁力校验、Torznab 解析、Internet Archive 映射、去重排序、响应上限和错误归一化。集成测试使用本地 HTTP 服务模拟搜索、种子下载、超时与错误响应，不依赖真实网站。IPC 测试确保渲染器只能传递经过验证的数据。

UI 冒烟测试检查搜索入口、三个标签、空结果、部分来源失败、导入成功和键盘操作。macOS 实机验证窗口、网页捕获与磁力导入；Windows 完成构建和静态冒烟检查。发布版本定为 `v0.2.0`，同步更新安装指南、GitHub Release 和飞书“工具库”。
