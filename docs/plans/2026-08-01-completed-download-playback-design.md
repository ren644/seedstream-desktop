# SeedStream 下载完成后本地播放设计

## 目标

下载任务完成后，用户仍可在文件清单中点击“播放”，直接使用 SeedStream 内置播放器观看已经保存到永久下载目录的视频。播放不依赖 Tracker、DHT、做种者或临时缓存，并且在应用重启、任务恢复后仍然可用。

## 方案选择

采用独立的本机回环媒体服务。完成态播放 URL 只包含随机会话令牌、任务 ID 和文件序号；引擎根据已验证的种子元数据解析实际文件路径。服务仅监听 `127.0.0.1`，只接受 `GET` 和 `HEAD`，并支持单段 HTTP Range，以兼容视频播放与拖动进度。

不直接向渲染进程暴露 `file://` 路径，避免平台差异和本地文件权限问题；也不在完成态重新加入 WebTorrent，因为本地播放不应重新等待节点或校验整个种子。

## 数据流

1. 下载完成后，任务保持 `complete` 和 `persistent` 状态。
2. 用户点击某个可播放文件的“播放”。
3. 引擎确认文件属于该任务、下载目录存在、实际文件是普通文件且大小与种子记录一致。
4. 引擎返回本机媒体 URL，并把播放来源标记为 `local`。
5. 内置播放器通过 Range 请求读取本地文件；关闭播放器只关闭播放状态，不删除永久文件。

若文件被移动、删除或大小不一致，界面显示明确错误并建议打开目录检查文件，而不是重新连接种子。

## UI 与错误处理

- 完成态保留每个视频文件的“播放”按钮。
- 本地播放显示“LOCAL PLAYBACK / 本地文件播放”，不显示节点搜索或缓冲诊断。
- 完成态任务操作区增加“播放视频”快捷按钮；多视频种子默认播放清单中的第一个可播放文件，其他文件仍可在清单逐个选择。
- 编码不受 Chromium 支持时，仍显示兼容性提示，并保留“打开目录”以便使用 VLC、IINA 等外部播放器。

## 验证

- 单元测试：完成态不重新添加 Torrent，返回本地播放 URL。
- HTTP 测试：完整响应、Range、HEAD、非法方法和越界访问。
- 恢复测试：应用重启后恢复 `complete` 任务，离线播放成功。
- 缺失文件测试：返回稳定错误码和用户可理解的提示。
- UI 冒烟：完成态显示“播放视频”，实际点击后播放器进入本地播放状态。
